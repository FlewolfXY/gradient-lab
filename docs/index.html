这是什么

学习一个陌生领域，不该先学会它的语言。这里把乐理翻译成画画的人已经懂的东西。所有计算都在你的浏览器里完成，画不会离开你的设备。

为什么是这样映射

不是像素 → 音符的花活，是画面 → 音乐决策的翻译。每一条规则都能用画画的人的直觉解释。

画面音乐为什么
全画主色相（饱和度加权，灰色不投票）走五度圈主音 / 调相邻色相 → 相邻的调，色环和五度圈都是圆
明度 + 冷暖大调 / 小调亮而暖的画很少是小调
扫描方向时间轴画 = 卷轴 / 瀑布 / 水面
每小节区域偏离全画基调的程度（排名）和弦功能：主 → 下属 → 属像基调 = 在家；偏得远 = 想回家
饱和度和弦张力：三和弦 → 加 7 → 加 9颜色越浓，声音越湿润复杂
明度音区高低亮 = 高
区域内最亮处的位置旋律轮廓旋律住在画面最亮处
边缘 / 细节密度节奏密度（近黑 = 休止）笔触密的地方音也密

硬规则保底：第 1 与最后 1 小节锁主和弦，每 4 小节拉向属和弦（终止式），所有和弦在调内，旋律强拍吸附和弦音。所以保证协和，丑也丑得在调上。随机性只留给力度与微小的时值抖动——同一幅画、同一个种子，永远召唤出同一首曲子。

已知的边界：当一幅画有两个势均力敌的色彩阵营（比如火焰与蓝色机器人），饱和度加权的平均色相会落在两者之间一个并不存在的颜色上。下一版会检测双色调对峙，让主色定调、副色变成"外来和弦"。

Score → Layers · 音乐解剖台

这是同一个论点的反方向：上传一段音频，把它拆成能看、能点、能循环的"图层面板"——波形、CQT 音高谱、Mel 频谱、十二音级色带、三段响度曲线、和弦候选、段落边界与自相似矩阵，并为每一段生成一句人话（"不是更响，是更亮"）。

它依赖 Python 端的 librosa，目前作为本地工具随仓库提供。运行方式见 audio-xray/。
